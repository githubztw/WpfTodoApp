# Feature Specification: WPF 多模块任务管理系统

**Feature Branch**: `001-wpf-task-management`

**Created**: 2026-06-08

**Status**: Draft

**Input**: User description: "构建以一个多模块WPF项目
1. 用户管理模块：对用户包括密码在内的信息增删改查
2. 登录模块：用户登录，首次启动默认用户：admin, 密码：123456，用户首次登录成功后，提示用户修改密码
3. 办事项管理（TodoList）模块：管理用户日常任务。用户可以添加、编辑、完成和删除任务。
任务应按创建时间排序，并可切换查看 "全部任务"、" 已完成任务 "、"未完成任务"。
用户应能为任务添加截止日期和优先级，应用需要在任务到期10分钟前提醒用户。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 用户登录与首次密码修改 (Priority: P1)

系统启动时展示登录界面。用户输入用户名和密码进行身份验证。首次启动时系统存在默认管理员账户（用户名：admin，密码：123456）。当该默认账户首次登录成功后，系统强制引导用户修改密码，新密码须满足复杂度要求。修改成功后，用户进入主界面。后续登录使用新密码。

**Why this priority**: 登录是系统的入口关卡，所有用户必须通过身份验证才能使用任何功能。首次密码修改是安全基线要求，防止默认凭证被恶意利用。

**Independent Test**: 可通过启动应用 → 输入 admin/123456 → 被引导修改密码 → 修改成功进入主界面 → 退出 → 用新密码重新登录，完整验证整个登录闭环。

**Acceptance Scenarios**:

1. **Given** 系统首次启动且仅有默认 admin 账户，**When** 用户输入 admin/123456 并点击登录，**Then** 系统认证通过并显示密码修改界面，提示用户修改密码。

2. **Given** 用户在密码修改界面，**When** 用户输入符合复杂度要求的新密码并确认，**Then** 密码修改成功，用户进入主界面，旧密码（123456）立即失效。

3. **Given** 用户在密码修改界面，**When** 用户输入的新密码与确认密码不一致，**Then** 系统显示错误提示"两次输入的密码不一致"，要求用户重新输入。

4. **Given** 用户在密码修改界面，**When** 用户输入的新密码不满足复杂度要求（少于6位或无字母数字混合），**Then** 系统显示具体复杂度要求提示，拒绝该密码。

5. **Given** admin 用户已完成首次密码修改，**When** 用户再次使用 admin/123456 登录，**Then** 系统拒绝登录并提示"用户名或密码错误"。

6. **Given** 存在一个已修改过密码的普通用户，**When** 该用户使用正确凭证登录，**Then** 系统直接进入主界面，不显示密码修改界面。

---

### User Story 2 - 用户管理 (Priority: P2)

管理员（admin 账户）登录后可通过用户管理界面对系统内所有用户进行管理，包括查看用户列表、创建新用户、编辑用户信息、删除用户。用户信息包含用户名和密码。所有密码须满足复杂度要求。

**Why this priority**: 用户管理是多用户系统的基础设施，但系统的核心价值在 TodoList 模块。在 MVP 阶段，admin 默认账户已可满足单人或小团队使用，用户管理可在后续迭代中完善。

**Independent Test**: 以管理员身份登录 → 进入用户管理 → 创建新用户 → 查看用户列表确认新用户存在 → 编辑该用户信息 → 用新用户凭证登录验证 → 以管理员身份删除该用户 → 确认被删除用户无法登录。

**Acceptance Scenarios**:

1. **Given** 管理员已登录并进入用户管理界面，**When** 管理员点击"添加用户"，**Then** 系统显示用户创建表单（用户名、密码、确认密码）。

2. **Given** 管理员填写了有效的用户名和符合复杂度要求的密码，**When** 管理员点击"保存"，**Then** 新用户创建成功并出现在用户列表中。

3. **Given** 管理员在用户创建表单中，**When** 管理员输入的用户名已存在，**Then** 系统提示"用户名已存在"并拒绝创建。

4. **Given** 用户列表显示所有用户，**When** 管理员选中某用户并修改其密码，**Then** 用户密码更新成功，旧密码立即失效。

5. **Given** 管理员选中某非管理员用户，**When** 管理员点击"删除"并确认，**Then** 该用户被移除且无法再登录系统。

6. **Given** 管理员选中 admin 账户，**When** 管理员尝试删除，**Then** 系统拒绝并提示"无法删除内置管理员账户"。

7. **Given** 非管理员用户已登录，**When** 该用户尝试访问用户管理功能，**Then** 系统拒绝访问，用户管理入口不可见或禁用。

---

### User Story 3 - 办事项（Todo）核心管理 (Priority: P1)

用户登录后可查看自己的办事项列表。用户可以添加新任务、编辑任务内容、标记任务为已完成、删除任务。任务列表默认按创建时间降序排列（最新在前）。用户可通过筛选器切换查看"全部任务"、"已完成任务"和"未完成任务"。

**Why this priority**: 任务管理是用户使用本系统的核心目的。P1 范围覆盖 CRUD + 排序 + 筛选，构成最小可用产品。

**Independent Test**: 登录 → 添加多个任务 → 验证列表按创建时间排序 → 编辑某任务内容 → 标记某任务为完成 → 切换筛选器查看不同视图 → 删除某任务 → 验证任务消失。

**Acceptance Scenarios**:

1. **Given** 用户已登录并进入 TodoList 界面，**When** 用户点击"添加任务"，**Then** 系统显示任务创建表单（标题、描述）。

2. **Given** 用户在任务创建表单中，**When** 用户输入标题并点击"保存"，**Then** 新任务出现在列表顶部（最新创建排最前），系统显示创建时间。

3. **Given** 任务列表中存在多个任务，**When** 用户查看列表默认视图，**Then** 所有任务按创建时间降序排列。

4. **Given** 用户在某任务上点击"编辑"，**When** 用户修改标题/描述并保存，**Then** 任务信息更新，列表中反映最新内容。

5. **Given** 用户在某未完成任务上点击"完成"，**When** 操作执行，**Then** 该任务标记为已完成状态，视觉上与非完成状态有明显区分。

6. **Given** 用户在筛选器中选择"已完成任务"，**When** 列表刷新，**Then** 仅显示状态为已完成的任务。

7. **Given** 用户在筛选器中选择"未完成任务"，**When** 列表刷新，**Then** 仅显示状态为未完成的任务。

8. **Given** 用户在筛选器中选择"全部任务"，**When** 列表刷新，**Then** 显示所有任务，不区分完成状态。

9. **Given** 用户在某任务上点击"删除"，**When** 用户确认删除，**Then** 该任务从列表中移除且不可恢复。

### User Story 4 - 任务优先级与截止日期 + 到期提醒 (Priority: P2)

用户在创建或编辑任务时可设置截止日期（可选）和优先级（高/中/低）。任务列表中显示各任务的截止日期和优先级标识。对于设置了截止日期且未完成的任务，系统在任务到期前10分钟向用户发送提醒通知。

**Why this priority**: 优先级和截止日期显著提升任务管理的实用性，到期提醒是差异化价值点。但核心 CRUD 功能（US3）必须先就位，此故事在其之上叠加。

**Independent Test**: 创建带截止日期（设为当前时间+5分钟）的高优先级任务 → 验证列表中显示优先级和截止日期 → 等待约5分钟 → 验证系统弹出到期提醒通知 → 创建无截止日期的任务 → 验证该任务不触发提醒。

**Acceptance Scenarios**:

1. **Given** 用户在任务创建/编辑表单中，**When** 用户选择一个截止日期，**Then** 该日期与任务关联保存，列表中展示截止日期。

2. **Given** 用户在任务创建/编辑表单中，**When** 用户选择优先级（高/中/低），**Then** 优先级与任务关联保存，列表中用视觉标识区分不同优先级。

3. **Given** 用户创建任务时未设置截止日期，**When** 任务保存，**Then** 该任务不显示截止日期，且不触发任何到期提醒。

4. **Given** 某未完成任务设置了截止日期为 T，**When** 系统时间到达 T-10 分钟，**Then** 系统弹出桌面通知提醒用户该任务即将到期。

5. **Given** 某未完成任务设置了截止日期为 T，**When** 系统时间到达 T-10 分钟但任务已被标记为完成，**Then** 系统不发送提醒。

6. **Given** 用户设置了截止日期为过去的任务，**When** 任务被保存，**Then** 系统提示"截止日期已过期"，但仍然允许保存，列表中该任务标记为"已过期"。

---

### Edge Cases

- 用户同时打开多个任务编辑窗口时，数据一致性如何处理？（假设：同一任务同一时间只能在一个编辑窗口中打开，使用模态对话框避免并发编辑）
- 系统时间被用户手动修改时，提醒功能如何处理？（假设：使用系统本地时间，不进行 NTP 校时——这是桌面应用的标准做法）
- 应用关闭期间有任务到期时，到期提醒如何处理？（假设：应用启动时检查所有未完成且有截止日期的任务，对已过期未提醒的任务立即触发提醒）
- 多个任务在同一时间（或相近时间）到期时，提醒如何展示？（假设：每个任务独立发送通知，按截止时间先后逐一弹出）
- admin 用户自己能否删除自己的账户？（假设：不可以，admin 账户受保护，不可删除）
- 用户可拥有的最大任务数量？（假设：无硬性限制，当任务超过 500 条时建议启用归档功能）

## Requirements *(mandatory)*

### Functional Requirements

**登录与认证**

- **FR-001**: 系统 MUST 在启动时展示登录界面，要求用户输入用户名和密码。
- **FR-002**: 系统 MUST 在首次启动时预置默认管理员账户（用户名：admin，密码：123456），并标记该账户为"首次登录"状态。
- **FR-003**: 系统 MUST 在默认管理员首次登录成功后将用户引导至密码修改界面，用户必须修改密码才能进入主界面。
- **FR-004**: 系统 MUST 验证密码复杂度——新密码长度不少于6位，且必须包含字母和数字。
- **FR-005**: 系统 MUST 验证两次输入的新密码一致，不一致时拒绝修改并提示用户。
- **FR-006**: 系统 MUST 在密码修改成功后使旧密码（默认 123456）立即失效。
- **FR-007**: 系统 MUST 对所有普通用户的登录进行凭证验证，验证通过后直接进入主界面。

**用户管理**

- **FR-008**: 系统 MUST 允许管理员查看所有用户的列表。
- **FR-009**: 系统 MUST 允许管理员创建新用户，需要提供用户名、密码。
- **FR-010**: 系统 MUST 验证新用户名在系统中唯一，重复时拒绝创建并提示。
- **FR-011**: 系统 MUST 允许管理员编辑已有用户的密码。
- **FR-012**: 系统 MUST 允许管理员删除非管理员用户，删除前需要确认。
- **FR-013**: 系统 MUST 禁止删除内置 admin 账户。
- **FR-014**: 系统 MUST 限制用户管理功能仅对管理员账户开放，非管理员用户无法访问。

**TodoList 核心功能**

- **FR-015**: 系统 MUST 允许用户创建新任务，至少包含标题（必填）和描述（可选）。
- **FR-016**: 系统 MUST 允许用户编辑已有任务的全部字段。
- **FR-017**: 系统 MUST 允许用户将任务标记为"已完成"状态。
- **FR-018**: 系统 MUST 允许用户删除任务，删除前需要确认，删除后不可恢复。
- **FR-019**: 系统 MUST 将任务列表默认按创建时间降序排列（最新创建的任务在最前面）。
- **FR-020**: 系统 MUST 提供筛选器，允许用户切换查看：全部任务、仅已完成任务、仅未完成任务。
- **FR-021**: 每个用户的 TodoList 数据 MUST 相互隔离，用户仅能查看和管理自己的任务。

**优先级、截止日期与提醒**

- **FR-022**: 系统 MUST 允许用户在创建/编辑任务时设置截止日期（可选字段）。
- **FR-023**: 系统 MUST 允许用户在创建/编辑任务时设置优先级（高/中/低），默认为"中"。
- **FR-024**: 系统 MUST 对设置了截止日期且未完成的任务，在截止时间前10分钟触发桌面提醒通知。
- **FR-025**: 系统 MUST 在提醒触发时，在通知中展示任务标题和截止时间。
- **FR-026**: 系统 MUST 在应用启动时检查所有未完成且有截止日期的任务，对已过期且未提醒的任务补发提醒。

### Key Entities

- **User（用户）**: 系统的使用者。关键属性：用户名（唯一标识）、密码哈希、是否为管理员、是否为首次登录。
- **TodoItem（办事项）**: 用户创建的任务。关键属性：标题、描述、创建时间、截止日期（可选）、优先级（高/中/低）、完成状态（布尔）。所属用户（外键关联）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户可在 30 秒内完成登录流程（首次登录含密码修改在 90 秒内完成）。
- **SC-002**: 管理员可在 2 分钟内完成新用户的创建，全程步骤不超过 4 次点击。
- **SC-003**: 用户可在 15 秒内完成一条新任务的添加。
- **SC-004**: 任务列表在包含 500 条任务时仍保持流畅滚动（无可见卡顿）。
- **SC-005**: 到期提醒在目标时间 ±30 秒内触发（应用处于运行状态时）。
- **SC-006**: 90% 的测试用户在无说明文档的情况下可独立完成登录、创建任务、标记完成的核心操作路径。
- **SC-007**: 用户数据在应用异常关闭（如断电）后不丢失，重启后恢复到最后一次保存状态。

## Assumptions

- 系统为单机桌面应用，数据存储于本地（SQLite 数据库）。
- 所有用户共享同一台 Windows 计算机，不支持网络多机访问。
- 密码以哈希形式（bcrypt 或等效算法）存储，明文从不落盘。
- 提醒通知使用 Windows 系统通知（Toast Notification）机制。
- 应用运行时存在后台定时器（每分钟检查一次），用于检测即将到期的任务。
- 用户会话绑定当前 Windows 用户，不支持同一 Windows 账户下应用内多用户同时登录。
- admin 账户不可删除、不可降级为非管理员。
- 系统语言为简体中文。
